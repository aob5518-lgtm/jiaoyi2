# Hyper-Safe Quant V5.0：代码审计与技术架构

日期：2026-11-06；开发基线 main：0681f2b78cffd9fbaee316b5c10426c97df99fb1。

## 审计结论

实际仓库是 Node 单进程 HTTP 服务、文件型 JSON 账本与原生 HTML/JS 前端，没有数据库迁移层。server.js 同时调度 Classic/Smart、Trend Runtime、4H Runtime；terminal/policy.js 管理 Legacy 限制与新账户入口；terminal/migration-audit.js 保留迁移证据、权益核验与回滚。V3、Short-Term、4H 有各自独立策略模块，订单适配与部分风控在 server.js 内耦合。

因此 H01 不复用旧账户交易控制器、不注册成一个可被旧 Live 接口启动的 CORE 账户，也不为旧策略重命名。它通过新的确定性策略注册表暴露于独立研究工作区，使用单独的 Research/Shadow 账本。没有修改原有策略核心文件、配置参数、账户数据、历史或迁移代码。

保留并复用：trend_only.indicatorsFor 的纯 ATR/ADX 计算、trade_cost 的成本建模、trend_v3/portfolio 的纯组合敞口校验。旧 V1 的策略判断、CHOP 过滤、ADX 上升要求不参与 H01 判断；只使用其不访问网络的纯指标函数。

本次只增加 server.js 的认证 V5 路由与关闭时刷盘钩子；旧 API 和调度保持。主站首次访问 /api/v5/status 不创建研究账户，不触碰原有 config/auth/runtime。附加入口置于原终端页脚，原五项导航和三策略入口保留。

## 执行链

公共已收盘行情 → 市场质量核验 → 4H 状态 → 1H 收盘突破/量能 → UTC 周末门禁 → 原生报价与规格 → 风险反推仓位 → 共享研究组合限额 → 虚拟订单提交 → 后续独立报价成交 → 模拟保护止损 → 跟踪/候选退出 → 净账本结算与下一笔权益。

Research 和 Shadow 使用同一 market.evaluate/book.step 实现。历史回放在当前 15m 开盘阶段仅能使用之前已生成的信号，随后到收盘阶段才观察完整 OHLC 并计算新信号。下单不会按突破收盘价零成本追溯成交。入场相应两毫秒事件序号只是同时间边界的稳定排序，不宣称毫秒撮合精度。

## 模式与凭据边界

只允许 Research/Shadow，注册表、scope、创建/控制 API 均拒绝 Live；H02—04 没有执行入口。数据适配器不包含签名、账户、下单、撤单、杠杆和转账方法。策略及虚拟账本不接受一个真实订单客户端作为依赖。

主站 API /api/v5/* 复用已有登录认证。独立服务只绑定 127.0.0.1，随机研究凭据写本地 0600 文件，服务器保存它用于验证 Bearer；浏览器仅在当前页面内存持有，不写 localStorage/sessionStorage。新建账户只允许 symbol/mode/config/initialEquity，拒绝凭据、地址、真实账户身份和任意权限字段；返回值递归过滤敏感字段，外部行情错误统一为安全错误码。

原生交易所保护单没有在 H01 中启用：Shadow 使用 SIMULATED_ACTIVE，并在保护失败时拒绝成交或进入安全退出。既有真实止损模块继续保留，但不因此声称 H01 已具备实盘原生保护能力。未来任何 Live 集成必须另行审批、对账及原生保护验证；本版本不能自动晋级。

## 风控与状态

默认单笔风险 0.3%、日亏损 2%、研究组合总风险 1.5%、最多两个持仓或待成交账户、杠杆上限10、保证金不超过权益50%。总风险完整相加 BTC/ETH 持仓及待成交，不给相关资产虚构分散化折扣。研究账户各有独立虚拟权益；不与生产账户资产合并，也不冒充真实交易所可用保证金。

计划用止损距离、双边手续费、压力滑点和资金费预留反推数量，并检查最小数量/名义、数量步长、最大量和估计强平空间。强平价格是保守研究估计，不是交易所实际清算价。跳空可超过计划预算，不能宣称止损保证最大亏损。

同一信号只能产生一笔虚拟订单。部分成交取消剩余量，未成交金额不计持仓。超时或撤单失败保留 UNKNOWN、保留待确认风险并锁定，后续过期或行情失败不自动洗成已取消。没有 API 强制解锁/删历史/重置权益。

暂停仅禁止新增风险，持仓仍参与保护。硬止损优先于同柱软退出和新跟踪止损，跟踪止损只向有利方向移动。旧仓位保存配置快照。硬止损后冷却8小时。日亏损以含浮动的权益判定，不能靠保持亏损仓位绕过日限额。

存储 schema=1，临时文件、fsync 和 rename 刷盘；账本损坏拒绝写入。订单成交量、平仓量和当前仓量必须相符；重复订单ID或错账锁定。独立进程目录锁防止同一服务双写。主站 integrated 与独立 standalone 使用不同子目录。

## 告警与 AI 权限

记录行情失联、保护失败、未知订单、核对异常；达到至少10笔前向成交且期望为负或回撤超候选日限额时记录 STRATEGY_DEVIATION。该告警是研究提示，不代表统计显著的失效判断。没有外部 AI 交易连接、无自然语言订单入口；不因告警调整参数或提升风险。

## 兼容性与未解决事项

原有账户及旧策略收益、权限、运行状态不迁移。新建数据只在 .v5-research，旧主站文件不更改。测试仅使用临时目录和模拟账户，当前任务未 SSH 生产、未部署、未发送真实订单。

已知旧4H报价时间问题仍按此前用户指示保留，本轮不以修复 V5 为由改变既有4H逻辑。现有 server.js 固定3000/0.0.0.0 的行为未改，独立 V5 服务提供明确的本机端口控制。

未完成的验证：多年度牛熊数据、历史真实盘口/队列、历史交易规格、组合联合回测、持续实时 Shadow、真实保护单和真实强平模型。补充收尾已用隔离headless Chrome完成桌面1440×1000与手机390×844、375×812实际渲染、截图和无横向溢出断言；不连接用户浏览器、不代表生产验收。

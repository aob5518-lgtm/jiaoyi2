- 本轮48组全部属于**已使用历史数据的研究**。2024—2025、2026-01-01至2026-06-29 00:00 UTC（右端不含）均已在上一轮被查看，不能重新称为独立样本外。

- 原12组D/I/J的交易数、净收益、最大回撤均与固定基线一致，净收益差额均为0。新增观测不会改变这些经济结果。

具体原因：

1. 1x下，100%净保证金ROI要求净利润达到累计投入保证金本身；多仓通常需价格相对成本上涨超过约100%，还要覆盖费用。对没有正资金费补偿的1x空仓，即便价格趋近于零，扣费用后的净ROI仍低于100%。这个目标与小时MACD持仓周期存在明显尺度差异。
2. 实际管理路径中，各组最高净ROI仅9.55%—35.01%，连80%接近区间都未进入。目标未跨越是直接原因，原12组没有“已经达到目标但下单漏掉”的证据。
3. 96%—100%的完成轮次在目标前已因反向信号退出；其余4个实验轮次为硬止损。反向退出优先于普通分批止盈，而硬风险保护始终优先。这是当前规则的结果，不代表可安全取消退出。
4. 最高值是本回放保守路径的**观测值**，不是对未知真实盘中路径的保证。历史小时价格代理不能替代实时订单簿。
5. 独立合成场景在5x达到100%ROI时，目标观测、止盈订单、部分/完成成交和最终flag一致，且重启后不会重复执行。它验证机制，不计入Paper收益。

## 5. 工程整改清单

1. `book.js`：待成交首仓优先读取提交快照；所有订单含锁定配置与scope；记录唯一成交事件、累计数量、终结时间。补仓、分批、退出继续使用原轮次配置。
2. `runtime.js`：行情规格、MACD、参与率及风险核验使用当前轮次/首仓待成交快照；成交后结束为空仓时，不在同一tick把旧指标输入下一轮新配置。当前活动委托按账户当前快照统计，不因下一轮配置哈希改变而消失。
3. `diagnostics.js`：信号、提交、有部分成交、完成成交、退出及成交事件分别核对；订单ID/成交ID去重；窗口内新增与当前活动分离。落盘订单是权威来源，signalJournal缺行也可核对；旧记录缺事件不补造。
4. `h06-api.js`：首仓待成交时配置保存也明确返回下一轮生效；状态和分析接口接入持久化订单统计。
5. `audit.js`：只观测ROI、阶段浮亏与成本，结算时按真实数量分摊每层结果，不授权交易、不修改止盈止损。

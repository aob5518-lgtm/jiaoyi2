# H06 部署与回滚方案（本轮不执行生产部署）

1. 等待分支 PR 审查，不直接合并 main，不覆盖当前经典管理界面。重新核对 main、生产版本和本分支差异。
2. 用明确的最终 commit 在独立 release/stage 创建源码与锁文件依赖。禁止带入任何认证、API密钥、生产配置、旧账本及 `.h06-research`。
3. 先运行完整 `npm test`、`node tests/h06_visual_check.js` 和独立历史事件回放。核对 H06/旧策略权限、迁移审计和 Paper-only。
4. 所有旧 Live 账户在计划重启前必须完成只读原生持仓和委托核验；无法证明重启期间风险保护充分时中止。不能为了 H06 绕过旧 Live 安全检查。
5. 取得一致性备份：代码、依赖、配置、认证、全部历史/账本/运行时及发布标识。包括新 `macd_scale_in_runtime.json`；记录SHA256和账户数量。
6. 只发布代码，不覆盖任何生产JSON。新版首次出现 H06 不应修改旧账户策略、运行标志、权益或密钥。仅在明确授权后创建独立 H06 模拟账户，默认停止，不自动启动任何旧账户。
7. 在 stage 核对 `macd_scale_in_v1` 被策略目录识别、只支持 Binance ETH/BTC USDT永续，原生行情故障明确阻断。确认周期/价格/资金费率/合约规格均匹配。
8. 健康检查：公开接口、私有接口401、已认证终端、H06配置/历史、移动页面；未授权写操作403/400；所有真实下单入口对H06拒绝。
9. 故障时恢复部署前完整代码与依赖，清理该发布新增的代码文件。**不得恢复旧运行时覆盖新生成的订单或历史**。
10. 若新版本已经产生 H06 Paper 持仓或待确认订单，不能直接回退到不认识 H06 的旧程序并抛弃其保护。先暂停新增，由仍支持该账本的 H06 隔离进程继续保护，或经明确确认后完成 Paper 安全退出与结算，再回滚主服务。

本机研究启动（独立状态目录，不是生产）：

```
node scripts/h06_forward.js --directory .h06-research --mode Shadow --symbol ETH --port 3376 --start
```

默认仅绑定127.0.0.1。认证文件在研究目录内，不应放入网页或GitHub。服务只开放带认证的 `GET /status`，不存在真实交易接口。停止该独立进程不等于平仓；若以后形成模拟持仓，应先保留/接管必要风险保护。

历史研究：

```
python scripts/h06_download.py --start 2020 --end 2025
node scripts/h06_replay.js .audit/h06-data docs/h06/research-results.json
```

所有历史结果是研究回放，不计入 Paper/Shadow 前向成绩。
